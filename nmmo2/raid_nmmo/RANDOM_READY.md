# 128人から毎試合6人を抽選する準備学習

独立方策128体、ボス01。学習中も6席それぞれに同じ128人名簿から重複なしで抽選し、次の試合には全員を戻す。準備の持ち越し記憶はない。支援職がゼロでも全員が準備完了なら出発する。16手で打ち切り、未出発は報酬0。出発後には選んだ職を保持し、既存の手書き方策がNMMO 2で30手以内のボス戦を行う。ボスのHP減少割合と討伐点を準備の全行動に割引なしで返す。役割や準備完了自体には報酬を与えない。

準備はバッチ処理用の専用環境。1手ごとに職指定・待機・完了切替のいずれかと、4種から1個の記号を同時に選ぶ。発言は次の手に全員に届く。自然言語、宛先、独立した沈黙操作はない。本人の職変更で本人の準備完了は自動解除され、同じ職を再指定しても解除されない。未配役から完了にはできない。環境は全員の操作を反映後に出発を判定する。

1体28,685パラメータ、味方埋込16・GRU幅64、重み共有なし。64試合ごとに独立IPPOを3エポック更新する。乱数seedによらず評価は同じ256組を使用。確率選択と最大確率選択を両方確認する。名簿全体を学習に使用するため、組全体が新規でも既知ペアが入り得る。

## 再現

リポジトリのルートから実行する。出力先は新しいフォルダを指定する。

```sh
nmmo2/.venv/bin/python -m nmmo2.raid_nmmo.random_ready --seed 41 --updates 100 --batch 64 --out runs/ready_reproduce41
nmmo2/.venv/bin/python -m nmmo2.raid_nmmo.ready_partner runs/ready_reproduce41
python3 nmmo2/raid_nmmo/summarize_ready.py runs/ready_reproduce41
```

試合ごとのJSONLでは jobs の各行が1手終了後の6人の職（-1未配役・0タンク・1ヒーラー・2DPS）。first は全6人の希望職が初めて埋まった時の並び、final は出発時または打ち切り時。最初に欠けた支援職を後で選んだ人は fillers に入る。集計時は「元の不足職が埋まったか」に加え「タンクとヒーラーが同時に存在したか」も確認する。任意の転職が相手への応答だったかは遷移だけでは判定できない。ready_partner は同じ乱数で1人の職をHまたはDに固定し、残りの5人の最終希望職が変わるかを測る。

## 完了時に職を確定する比較

`--lock-ready` を付けると、完了前は味方5人の希望職・完了状態・直前の発言を見て転職できる。職を選んで完了を押した本人は、その試合の準備中は職も完了状態も固定される。以降も記号通信は可能。全員の完了で即出発する。フラグなしは従来の完了切替。観測・報酬・ボス・制限時間・個体の重み数は両条件で共通。

学習前後の比較は同じ256組を確率選択および最大確率選択で評価する。完了固定そのものが勝率を上げ得るので、学習前の固定版も基準にする。職補完の比較では、同じ1,024組で一人の職をHまたはDに固定し、残り5人の最終希望職にHが含まれる割合を測る。通常評価の「途中で不足職が埋まった組数」は偶然の選び直しを含む。
