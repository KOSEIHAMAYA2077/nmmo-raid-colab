## 2. 観測・通信・行動

- `reset(seed=0)` は観測辞書を返す。初期状態はターン0、全員 DPS、生存、HP・MP 満タン、全 CD・敵視・トークンは0。観測には共通の `turn, in_prep, boss_hp` と、ID順の全員の配列 `jobs, hp, mp, alive, job_cd, skill_cd, skill2_cd, threat, last_comm` が入る。環境が返すのは一つの観測であり、自分の ID を表す別フィールドや個別視野はない。[初期化](env.py#L96)・[観測項目](env.py#L121)
- `step(actions, comms=None)` は各人の行動1個と任意の通信トークン1個を受け取り、`(obs, reward, done, info)` を返す。通信は行動と同時に選べ、準備・戦闘の両方で有効。生存者の送信値を語彙数で剰余化し、次の観測に全員分を載せる。省略すると全員0、死亡者の欄は最後の値を保持する。評価用の `info` に `won, boss_hp, alive_count, boss_target` が入る。最後の値は単体攻撃の対象 ID で、攻撃がなければ −1。[入力と通信](env.py#L153)・[戻り値](env.py#L296)

| 行動 ID | 効果 |
|---|---|
| 0 | 待機。 |
| 1 | 通常攻撃。ダメージ T/H/D = 5/5/20、加算する敵視は 25/5/20。 |
| 2 | T は挑発して、その時点の生存者の最高敵視＋100に自身の敵視を設定する。H は生存者で HP 割合が最低の1人を最大55回復する（同率なら小さい ID）。D は45ダメージ、敵視＋45の強撃。 |
| 3 | H は生存者全員を1人あたり最大25回復する。T と D では効果なし。 |
| 4 / 5 / 6 | T / H / D への転職。対応するジョブ ID は 0 / 1 / 2。 |

単体回復は有効回復量が正の場合に MP を消費し、CD を設定する。全体回復は発動すれば全員満タンでも MP を消費し、CD を設定する。回復による敵視は実際に戻した HP 合計の半分。スキルは CD・MP 条件を満たしたときに発動し、不発時の代替行動はない。[行動番号](env.py#L21)・[通常攻撃と固有スキル1](env.py#L183)・[全体回復](env.py#L226)

## 3. 1ターンの処理と勝敗

1. **準備**は最初の3ターン。通信と転職ができ、攻撃・スキル・ボスの反撃は発生しない。転職にはその人の1行動を使い、準備中の転職には CD が付かない。職を変えると HP は以前の割合に新しい最大値を掛けて丸める（最低1）。MP と敵視は引き継ぎ、固有スキルの CD は両方リセットする。戦闘中の転職には CD 10 が付く。[フェーズ](env.py#L116)・[転職](env.py#L137)・[準備中の処理](env.py#L170)
2. **戦闘**では全員の入力をまとめて受け取り、生存者の行動を ID 昇順に解決する。例えば、ヒーラー2人が同じ開始時観測から単体回復を選んでも、後のヒーラーの回復先は、先のヒーラーが回復したあとの HP 割合で決まる。[行動の処理順](env.py#L170)・[回復先の選択](env.py#L206)
3. プレイヤー全員の行動が終わりボス HP が0なら勝利し、そのターンの反撃を省く。生きているボスは敵視最大の生存者1人に単体攻撃（同率時は seed 付き乱数）。既定値では通常職に105、タンクに52.5、同ターンに挑発を使ったタンクに26.25入る。AoE の周期が正なら、戦闘開始を1と数えたその倍数ターンに単体攻撃の後で全生存者を攻撃する。AoE にもタンクの常時軽減を適用し、挑発の追加軽減は単体攻撃にだけ適用する。HP 0 の人は死亡し、敵視は0になる。蘇生はない。[討伐・単体攻撃](env.py#L241)・[AoE](env.py#L263)
4. 討伐済みでなければ、生存者の全 CD をターン末に1減らし、戦闘中は MP を10回復する（最大100）。**CD は付与ターン末にも減る。** ターン `t` に使用した CD 1 のスキルは `t+1`、CD 2 は `t+2` に再使用できる。単体回復 CD 0 と 1 は、どちらも毎ターン使える。ターン数を進め、全滅または準備＋戦闘ターンを消化したら終了。既定では最大33ステップ。[CD・終了判定](env.py#L277)
5. **共通報酬**はそのターンに減ったボス HP を初期ボス HP で割った値に、討伐ターンだけ1を加える。割引なしの合計は、負ければ削った割合、勝てば常に2。討伐時に3人生存でも6人生存でもこの合計は同じ。生存、所要ターン、敵視の移動、通信に個別の加点はない。[報酬式](env.py#L296)

## 4. 固定方策で再現できる結果

2026-11-16 に第6節の最初の2本のスクリプトを CPU で実行した。固定方策は各 ID の目標職を最初から与え、タンクは可能なら挑発、DPS は可能なら強撃する。ヒーラーの `smart` は生存者に HP 85% 未満がいれば単体回復、`smart_aoe` は該当者が3人以上いて発動可能なら全体回復を優先する。どの固定方策も通信を省略する。編成と行動は人が指定しているため、この集計で示せるのは各条件でその方策が攻略できたかまでである。[方策](sweep_checks.py#L79)・[評価ループ](sweep_checks.py#L38)

**人数と勝てた編成。** ボス単体攻撃105、AoE なし、戦闘30ターン。人数ごとに T/H/D の人数の全組合せを調べ、各編成を seed 0–4 で5回実行した。ID への割当は T→H→D の順で固定。表の勝利編成はすべて5勝で、それ以外は0勝。人数に合わせてボス HP も変えている。[人数別の条件・列挙方法](sweep_checks.py#L165)

| 人数 | ボス HP | 5勝した編成 | 敗戦編成で最も削れた例（残り HP） |
|---:|---:|---|---|
| 4 | 2100 | なし | 1:1:2（30、4人生存で時間切れ） |
| 5 | 2800 | 1:1:3 | 1:2:2（615） |
| 6 | 3500 | 1:1:4 | 1:2:3（340） |
| 8 | 5200 | 1:1:6 | 1:2:5（90） |
| 10 | 6800 | 1:1:8、1:2:7、2:1:7 | 1:3:6（635） |

**同じ編成でも行動で結果は変わる。** 既定の6人・1:1:4では標準方策は5勝・全員生存。挑発を通常攻撃に置き換えると0勝・平均報酬0.154・DPS 4人死亡。タンク待機は0勝・0.107、ヒーラーが通常攻撃だけなら0勝・0.381。単体回復を可能な限り選ぶ方策は5勝・全員生存。無行動／全7行動一様／全員 DPS の戦闘行動0–3一様は各20戦すべて敗れ、平均報酬は順に0.000／0.047／0.080だった。[役割行動の比較](sweep_checks.py#L190)・[ランダム基準](sweep_checks.py#L210)

**全体攻撃と回復。** 各行は5戦平均。回復 CD は（単体, 全体）を (0,0)／(1,3)／(0,3) の3条件で比較した。下表の勝数・生存数は3条件で一致した。`switches` はボス単体攻撃の対象変更回数である。[集計方法](sweep_checks.py#L38)・[設定と比較対象](sweep_checks.py#L224)

| N・ボス HP・攻撃・AoE | 編成・回復方策 | 勝数 | 生存 | 平均報酬・補足 |
|---|---|---:|---:|---|
| 6・3200・105・5ターンごと30 | 1:1:4 単体回復のみ | 5/5 | 3 | 2.000、対象変更2回 |
| 同上 | 1:1:4 単体／全体を使い分け | 5/5 | 6 | 2.000、対象変更0回 |
| 同上 | 1:1:4 可能な限り全体回復 | 0/5 | 0 | 0.452（CD 0,0）、0.453（他の2条件） |
| 10・5500・110・4ターンごと35 | 1:1:8 単体／全体を使い分け | 0/5 | 0 | 0.987、ボス残 HP 74 |
| 同上 | 1:2:7 単体／全体を使い分け | 5/5 | 10 | 2.000 |

10人の単体攻撃表と AoE 表ではボス HP と単体攻撃力も違うため、両表の差から AoE 単独の効果は推定できない。また上表は手書き方策に条件付けた結果であり、戦闘中の転職や別のスキル回しを含む全方策の最適編成、通信の必要性、役割の自発的な分担は未検証。全員の職を含む観測、固定 ID、ID 順の解決は、今後役割や通信の寄与を測るときに区別すべき手がかりとなる。[観測](env.py#L121)・[行動順](env.py#L170)・[割当](sweep_checks.py#L178)

## 5. 追加検証：10人で何を変えると勝てる編成が変わるか

前節の標準スクリプトに続き、人数10、単体攻撃110、戦闘30ターン、回復 CD (0,0)、同じ `smart_aoe` 方策と T→H→D の ID 順で条件を揃えた。各ボスで66編成すべてを seed 0–4 で試した。下表に載せた編成はすべて5勝、残りはすべて0勝だった。[全編成の結果 CSV](composition_audit.csv)・[使用した方策](sweep_checks.py#L79)

| ボス HP | AoE | 5戦すべて勝った編成 |
|---:|---|---|
| 5500 | なし | 1:1:8、1:2:7、1:3:6、2:1:7、2:2:6、3:0:7、3:1:6、4:0:6 |
| 5500 | 4ターンごとに35 | 1:2:7、1:3:6、2:2:6 |
| 7500 | なし | 1:1:8 |

**AoE の効果。** 最初の2行では AoE の有無だけが違う。今回の方策では勝てる編成が8通りから3通りになり、1:1:8 は全勝から全敗に変わった。両方で勝てる3編成があるため、この2条件に勝つだけならボスごとに編成を変える必要はない。[編成別集計](composition_audit.csv)

**編成の適応を測るボス候補。** 2行目と3行目には両方で勝てた編成がない。2ボスを等確率で出すと、上の固定方策・固定編成での最高勝率は50%。ボスの種類をあらかじめ知って `1:2:7` と `1:1:8` を割り当てれば100%に達する。これは2つの実測勝率からの計算で、学習済みエージェントの勝率ではない。この対は HP と AoE の2項目が違い、現行の共有観測では初期 HP だけでどちらか判別できる。その意味で、この対が試せるのはボスの違いに応じた役割選択まで。通信が必要になるかは別の比較が要る。[編成別集計](composition_audit.csv)・[準備時のボス HP 観測](env.py#L121)

**同日午後の追試。** 戦闘時の判断を変えると、両ボスに同じ 1:1:8・同一方策で勝てる。ヒーラーが味方の残 HP を見て全体回復の MP を温存する手書き方策では、環境 seed 0–99 で各ボス100戦全勝した。準備中の配役を固定し、通信と戦闘中の転職は使わない。単体攻撃ボスは平均10人、全体攻撃ボスは平均7人生存した。従来の `smart_aoe` の同じ1:1:8は、それぞれ100勝と0勝。同じ全体攻撃ボスで従来の1:2:7は100勝・平均10人生存。したがって上の50%という値は戦闘を従来方策に固定した比較に使う。勝率・生存人数・選ばれた編成をそれぞれ記録すれば、編成を変える利点と戦い方を変える利点を評価できる。[追試コード](design_counterexample.py)・[設計レビューと実測表](https://app.notion.com/p/41aeeebbd35681cdba24fb7a2a8a741d)

次のコマンドは同じリポジトリのルートから、追加検証の表について条件ごとの5戦全勝編成を表示する。

```sh
nmmo2/.venv/bin/python -B - <<'PY'
import sys
sys.path.insert(0, "nmmo2/raid_proto")
from env import JOB_DPS, JOB_HEALER, JOB_TANK, RaidConfig
from sweep_checks import make_comp_policy, run_policy

for hp, period in [(5500, 0), (5500, 4), (7500, 0)]:
    cfg = RaidConfig(num_agents=10, boss_hp=hp, boss_atk=110,
                     boss_aoe_interval=period, boss_aoe_dmg=35)
    winners = []
    for t in range(11):
        for h in range(11 - t):
            d = 10 - t - h
            jobs = [JOB_TANK] * t + [JOB_HEALER] * h + [JOB_DPS] * d
            policy = make_comp_policy(jobs, healer_mode="smart_aoe")
            if run_policy(cfg, policy, seeds=5)["win"] == 1:
                winners.append((t, h, d))
    print(hp, period, winners)
PY
```
